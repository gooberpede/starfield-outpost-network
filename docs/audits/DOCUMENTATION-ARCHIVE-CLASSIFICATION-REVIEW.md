## 2. Classification principles

Current authority, operational use, release evidence, active deferred-risk evidence, and capacity contracts stay loose. Completed briefs default to history. Transitional audits move when implementation or a later accepted synthesis owns their conclusion. Benchmarks stay only when the released configuration or current maintainer decisions still rely on them. A link alone does not force retention; current links to archived files are listed for later rewrite. No historical bytes are disposable.

## 3. Proposed archive structure and immutability policy

Later implementation should create `docs/implementation-briefs/ARCHIVE.md` plus `pre-1.0-implementation-history.zip`, `docs/audits/ARCHIVE.md` plus `pre-1.0-superseded-audits.zip`, and `docs/benchmarks/ARCHIVE.md` plus `pre-1.0-superseded-benchmarks.zip`. Preserve original filenames, bytes, and category-relative paths.

Once committed, each pre-1.0 ZIP should be immutable. Future batches should use new version- or date-bounded archives instead of rewriting these binaries. This model fits the repository: it preserves historical identity and avoids opaque binary churn. Each `ARCHIVE.md` must record the archive filename, release/date boundary, file count, SHA-256, reason, and a complete filename inventory so discovery never requires extracting the ZIP.
