## Verdict and decision boundary

**Not yet ready for deliberate public launch. The remaining path is finite and does not require finishing the backlog.** Five release gates remain: application/build identity; minimum About content; a usable support route; public-repository/licensing/publication sign-off; and acceptance of a frozen release candidate in disposable browser data. The first four can be prepared together after the user's decisions. Final deployment, repository publication and production indexing are **RELEASE DATE** operations, requiring later explicit authorization.

No new exposed credential, normal-use data-loss defect, or essential-workflow blocker was established by this audit. That is a bounded finding, not security, legal, accessibility or compatibility certification. Publication remains gated: pattern scanning does not establish that every historical record was intended to be public, and the existing notices do not establish redistribution rights for every asset and game-derived dataset.

The minimum path excludes on-demand overlays, caching changes, mobile/workspace redesign, a formal guide and V2 planning features. None of this report implements, approves, publishes or waives those changes. The supplied audit brief is the current task authority; historical recommendations are evidence rather than new instructions.

## Release gates: evidence and smallest closure

### Application version and build identity

`package.json` and the committed lockfile root both say `0.0.0`. `private: true` controls npm publication behavior; it is not GitHub visibility. No tags/releases were found. `AboutDialog.tsx` displays the application name, description and Flaticon attribution, but no application version. `vite.config.ts` has no application-version/commit injection.

**Recommendation, requiring user choice:** use `package.json` as the application-version source, keep the lockfile root synchronized, display that version plus a short commit in About, and record the full commit/deployment ID in release notes. Choose the first version and whether it is a prerelease before implementation; SemVer and a `v<version>` tag are proposals, not a selected `1.0.0` or authorization to create a release. A small build-time constant is sufficient; no automated release service is necessary. Cloudflare supplies `CF_PAGES_COMMIT_SHA` and `CF_PAGES_BRANCH`; a local build should identify itself explicitly as local/unknown when trustworthy Git metadata is unavailable, rather than fabricate an official release identity. [Cloudflare build configuration](https://developers.cloudflare.com/pages/configuration/build-configuration/).

Keep these identities separate: application version, collection schema version (currently 1), nested network schema version, reference manifest/dataset hash, locale codes and provenance/source-game versions. Changing the application version does not authorize a save migration. Completion requires one documented scheme and a tested correspondence among package metadata, About, release/tag naming and the deployed commit. A user disposition to retain less traceability must explicitly acknowledge weaker bug diagnosis; no waiver is granted here.

## Bounded investigations and restart evidence

### Long-name evidence and backup limitations

New in-memory probes used the real serializer/deserializer and filename helper, without reading or writing browser storage:

- A default collection with the name `Release smoke` serialized and deserialized identically; its sample filename retained name, level, timestamp and `.json`.
- A 4,096-letter name produced a 4,138-character filename. Source sanitizes to an ASCII slug but never truncates its fragment.
- A 4,097-letter name exported by the serializer was rejected on re-import with `string-too-long`. External import caps each string at 4,096 UTF-16 units; storage's separate cap is 16,384, and the character input has no `maxLength`. The same differing-envelope principle applies to very large/modded collections.

This is a real **outlier round-trip limitation**, not evidence that ordinary 25-character gameplay names or supported normal collections fail. The earlier 16 September named-browser capacity report verified real export/re-import in Edge, Chrome and Firefox, while Edge truncated the extreme filename and lost its timestamp. No silent application truncation or actual normal-use loss was observed here. Preserve the polish priority, document that exports outside the external-import envelope are not guaranteed directly re-importable, and make normal-size round-trip acceptance explicit. Do not fix the mismatch by silently truncating saved names, raising defensive limits or imposing the tentative 196-character ceiling. A later safeguard should preserve canonical data and reserve a bounded filename suffix separately from status-text display.
